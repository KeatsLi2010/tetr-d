# ADR-0002：本地 Handling 与离散操作流

- 状态：已接受
- 日期：2026-07-26

## 决策

玩家的键位与 Handling 配置全部保存在浏览器本地。客户端将持续按键按
DAS、ARR、DCD、SDF 等本地参数展开为离散操作，再把有序操作上传：

- `moveStep`：横移一格；
- `moveToWall`：ARR 为 0 时移到该方向的最远合法位置；
- `softDropStep`：软降指定格数；
- `sonicDrop`：降到最低合法位置但不锁定；
- `hardDrop`、`rotate`、`hold`；
- `clearHeld`：焦点丢失或输入上下文切换时的有序屏障。

服务器不知道玩家的键位或 Handling 值，只校验消息形状、顺序、基础预算，
并权威执行碰撞、旋转、锁定、攻击、垃圾与胜负。

## 延迟策略

输入采用流水线式乐观执行，不采用逐操作确认：

1. 本机生成离散操作；
2. 本机预测器立即执行；
3. 操作按 `inputEpoch + sequence` 连续编号并发送；
4. 客户端不等待 ACK，继续生成后续操作；
5. ACK 用于清理 outbox，snapshot/hash 用于发现并校正偏差。

因此一个 RTT 内可以有多条输入在途。同一客户端帧的操作保持 DOM 事件顺序，
最多 16 个操作组成一条消息，超出时稳定分包。

## 配置表示

ARR、DAS、DCD 使用“十分之一 60Hz 参考帧”的整数：

- `1F = 16.666…ms`；
- ARR：`0..5F`；
- DAS：`1..20F`；
- DCD：`0..20F`；
- SDF：`5..40`，或 `sonic`。

传统帧只用于表达设置；本地输入时钟按对局的 `simulationHz` 展开，当前默认
240Hz。不得把 `1F` 误当成一个 240Hz tick。

## 结果与取舍

优点：

- 本地按键不受 RTT 阻塞；
- 不需要向服务器公开或同步个人配置；
- 回放只依赖离散操作，不依赖产生操作时的键位和 Handling；
- ARR 0 和音速降使用单个原子操作，减少消息量。

代价：

- 服务器无法区分合法的极速本地配置与宏；
- 修改客户端可以直接生成最快合法操作；
- 本方案不是强反作弊模型。

项目当前仅面向不超过 10 名可信用户，明确接受该风险，优先保证操作手感。
如果未来公开运营，应重新评估服务器冻结 Handling、操作成本审计或反作弊层。
