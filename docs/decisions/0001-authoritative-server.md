# ADR-0001：采用服务器权威模拟与客户端预测

- 状态：接受
- 日期：2026-07-25

## 决策

每个对局由独立 Match Coordinator（可按 match actor 组织）以可配置的固定步进执行权威模拟，默认 240 Hz，允许通过 `MATCH_TICK_RATE_HZ` 在 `60..1000` 范围调整。RoomActor 只管理房间、番战和开局生命周期。浏览器使用完全相同的 `game-core` 对自己的棋盘进行预测，并通过 input ack、state hash 和 snapshot 校正；对手棋盘只做表现层插值。

实现状态（2026-07-26）：服务端已接入 Match Registry、Coordinator、比赛输入/重同步/投降消息、30 Hz snapshot 与 `match.end`；浏览器预测和完整可玩界面仍未实现。

## 原因

- 服务器可验证方块序列、移动、攻击和 KO，明显缩小作弊面。
- seed + 带权威应用 frame 的输入日志可以确定性回放、观战、重连和复核战绩。
- RoomActor 串行化房间命令，Match Coordinator 串行化比赛输入、tick 和裁决，分别约束 WebSocket、定时器与断线事件的并发。
- 客户端预测不牺牲高延迟环境下的按键手感。

## 代价

- 客户端与服务器核心必须逐版本保持位级一致。
- 需要状态哈希、回滚/重放和快照协议。
- 服务器 CPU 成本高于纯客户端裁决；当前小规模（不超过 10 人）由单进程 Registry 驱动，后续扩容仍需要按 match 分片和容量测试。

## 否决方案

- 客户端上报落点/攻击：实现快但无法可信裁决。
- 纯 lockstep 等待双方输入：安全性仍有限且延迟直接影响手感。
- P2P：浏览器网络可达性、作弊、观战和重连复杂度均不适合首版。
